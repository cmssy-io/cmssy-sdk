# Migrating from v18 to v19

v19 makes `ResolvedMedia.type` **required** and adds `ResolvedMedia.duration`.
Both fields have existed on the delivery API since CMS-1970 and CMS-1969; the SDK
simply pinned `@cmssy/types` below the version that declares them, so no site
could see either one. That pin is what this release fixes.

Two new helpers come with it, `mediaType` and `mediaDuration`, plus the
`MediaType` union and its `mediaTypeValues` vector.

There is **no codemod.** Nothing moved and nothing was renamed, so there is no
import to rewrite. The one thing that can break is a value you construct
yourself, and only TypeScript can tell you where those are.

## Why it is a major

Reading a field that went from optional to required never breaks a reader - it is
a stronger guarantee, not a weaker one. What breaks is **writing** one:

```ts
const fixture: ResolvedMedia = {
  url: "https://assets.example/hero.jpg",
  alt: "Hero",
  //  ^ Property 'type' is missing in type '{ url: string; alt: string; }'
  //    but required in type 'ResolvedMedia'
};
```

Every test fixture, mock, Storybook arg and seed value you hand-write gets this
error. Add the kind:

```ts
const fixture: ResolvedMedia = {
  url: "https://assets.example/hero.jpg",
  alt: "Hero",
  type: "image",
};
```

`type` is one of `"image"`, `"video"`, `"document"`, `"audio"`. Import the union
as `MediaType`, or the runtime vector as `mediaTypeValues` if you need to iterate
it.

The second reason is less visible and matters more if you do not run cmssy.io: a
required field is an assertion about what your backend sends. **A cmssy older
than 2026-10-01 does not send `type`**, so the SDK would type it as `MediaType`
while handing you `undefined` at runtime. If you self-host, upgrade cmssy before
upgrading the SDK.

## What you get

A mixed gallery is the case this unblocks. Before v19 a resolved media value
carried a URL and alt text and nothing that told a photo from a clip, so a
gallery had to guess from the file extension - which fails on a CDN URL with no
extension, and on every `document` and `audio` asset.

```tsx
import { mediaType, mediaDuration } from "@cmssy/core";

function Gallery({ items }: { items: ResolvedMedia[] }) {
  return items.map((item) =>
    mediaType(item) === "video" ? (
      <video key={item.url} src={item.url} />
    ) : (
      <img key={item.url} src={item.url} alt={item.alt ?? ""} />
    ),
  );
}
```

Both helpers accept the same `MediaLike` a plain string URL satisfies, and both
return `undefined` for one - a bare string carries no kind and no duration, so
there is nothing to report. That is why they are helpers rather than property
reads: the field is required on `ResolvedMedia`, but the values your content
hands you are not all `ResolvedMedia`.

`mediaDuration` returns seconds, and only for assets whose upload decoded a
duration. Audio and video have one; images and documents do not.

## Checklist

1. Upgrade cmssy first if you self-host. `type` and `duration` reach the
   delivery API in the 2026-10-01 release.
2. Bump all `@cmssy/*` packages together. They move in lockstep and the peer
   ranges on `@cmssy/next`, `@cmssy/astro` and `@cmssy/remix` now ask for
   `@cmssy/react` ^19.
3. Run `tsc`. Every error is a `ResolvedMedia` you build by hand; add `type`.
4. Replace any file-extension sniffing in your galleries with `mediaType`.
