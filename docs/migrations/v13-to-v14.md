# v13 → v14

The settings a layout region has stop being cmssy's fixed pair and become a schema your site declares, the way a block declares `props`.

## What changed

`@cmssy/core`, `@cmssy/react` and `@cmssy/types` no longer export `CmssyLayoutSettings` (`{ desktopWidth, mobileBehavior }`). `CmssyLayoutGroup.settings` is now `Record<string, unknown> | null`: the values of whatever schema you declared on that region, or `null` when nothing was authored. In their place:

```ts
// cmssy.config.ts
import { defineCmssyConfig, defineCmssyLayout } from "@cmssy/next";
import { fields } from "@cmssy/core";

export const layout = defineCmssyLayout({
  regions: [
    { id: "header", label: "Header" },
    {
      id: "sidebar_left",
      label: "Aside",
      settings: {
        showOnMobile: fields.boolean({ label: "Show on mobile" }),
        width: fields.number({ label: "Width (px)", required: true }),
      },
    },
  ],
});
```

`settings` takes exactly the schema type a block's `props` takes, so every `fields.*` builder works there. The editor renders a form from it on the Layouts page and stores the values as JSON; `CmssyRegionSettings<typeof layout, "sidebar_left">` is the typed value object (`{ showOnMobile?: boolean; width: number }` here), inferred the way block content is inferred from `props`. A region without `settings` has no settings at all. The edit page announces the schema to the editor in `cmssy:ready` next to the region ids; nothing changes on Astro or React Router beyond what v13 already had you pass through.

The public `layouts` query the SDK sends now selects `settings` as a bare JSON scalar. Needs the admin side, live on cmssy.io: a site on 14 against a backend without CMS-1704 gets a 400 on every page that mounts a layout slot, so upgrade only once the backend is there.

## Why

`desktopWidth` and `mobileBehavior` were cmssy's guess at what a sidebar needs. Nothing in cmssy or the SDK ever rendered them, and a site with a cookie bar or a promo strip needed different knobs. Now the site says what each region needs, the editor shows exactly that, and the compiler types the values.

## What you change

1. If your own code read `group.settings.desktopWidth` / `mobileBehavior`, declare those (or whatever the region really needs) as `settings` on the region and read them back through `CmssyRegionSettings`:

```diff
-const width = group.settings?.desktopWidth ?? 280;
+const settings = group.settings as CmssyRegionSettings<typeof layout, "sidebar_left"> | null;
+const width = settings?.width ?? 280;
```

2. If you wrote your own `PublicPageLayouts` operation, drop the sub-selection:

```diff
 layouts(workspaceSlug: $workspaceSlug, pageSlug: $pageSlug, previewSecret: $previewSecret) {
   position
   blocks { id type content style advanced order isActive }
-  settings { desktopWidth mobileBehavior }
+  settings
 }
```

3. `@cmssy/types` moves to 0.38.0 with the packages.

Values authored under the old pair are cleared by cmssy on upgrade; a region shows its form empty until you fill it in.
