# Migrating from v16 to v17

v17 stops the SDK declaring by hand what the CMS already knows. Two things that
were hand-written copies of the delivery schema now come from one place, and
both had drifted away from what the API serves.

There is **no codemod**. Nothing moved and nothing was renamed, so no import
specifier changes. The whole migration is one command and, in some codebases,
deleting null checks that can no longer fire.

## Run this and commit the result

```bash
npx @cmssy/cli types
```

Your `graphql/models.ts` is now out of date by its own header, so
`cmssy types --check` in CI will fail until you regenerate and commit. That is
the one required step.

## What changed in the generated file

The preamble used to declare four shapes itself. It now imports them from
`@cmssy/core` and re-exports them under the same names, so **nothing you import
from the generated file changes**:

```ts
import type {
  CmssyLocalizedValue as CmssyLocalized,
  ResolvedMedia as CmssyMedia,
  FileFieldValue as CmssyFile,
  CmssyModelRecord as CmssyRecordOf,
} from "@cmssy/core";

export type { CmssyLocalized, CmssyMedia, CmssyFile, CmssyRecordOf };
```

Three of the four copies were narrower than the real shape:

| shape | v16 copy | v17, the real type |
| -- | -- | -- |
| `CmssyMedia` | six members | also `altText` and `transform`, both served by the delivery API |
| `CmssyLocalized` | `string \| Record<string, string>` | `Record<string, string> \| string \| null` |
| `CmssyRecordOf` | `status`, `createdAt`, `updatedAt` non-null | all three nullable |

So `media.altText` and `media.transform` are readable without a cast for the
first time, and the three record members plus **every localized field in every
generated interface** gained `| null`. If you already pass localized values to a
helper that takes `unknown`, nothing changes. If you pass them somewhere that
wants a `string`, that call site now needs the narrowing it always needed.

The generated file now depends on `@cmssy/core` exporting those four names, so
it needs a v17 core. `cmssy types` says so by name - naming the installed
version and the missing shapes - rather than leaving `tsc` to blame
`@cmssy/core`.

## What changed in the form types

`@cmssy/core` re-exports the form shapes from `@cmssy/types`, which stopped
contradicting the delivery schema. Five fields the API never returns as null
were declared nullable:

| field | v16 | v17 |
| -- | -- | -- |
| `CmssyFormDefinition.slug` | `string \| null` | `string` |
| `CmssyFormDefinition.settings` | `CmssyFormSettings \| null` | `CmssyFormSettings` |
| `CmssyFormSettings.actionType` | `string \| null` | `"contact" \| "custom"` |
| `CmssyFormSettings.requireLogin` | `boolean \| null` | `boolean` |
| `CmssyFormSubmitResponse.message` | `string \| null` | `string` |

If you guarded any of these against null, you can delete the guard. If you
**construct** a form definition - a test fixture, a mock, a preview - you now
have to supply a slug and a settings object.

Six localized fields are `Record<string, string> | string` rather than
`string | null` or `unknown`: `label`, `placeholder` and `helpText` on a field,
and `submitButtonLabel`, `successMessage` and `errorMessage` on the settings.
They always held a locale map; the old declaration said otherwise and every
working consumer routed around it.

Four fields that were `unknown` now have shapes: `options` is
`FormFieldOption[]`, `validation` is `FormFieldValidation`, `defaultValue` is
`string | null`, and `fieldType` is the `FormFieldType` union rather than a bare
string. If you were casting to read a select field's options or a field's
validation rules, delete the cast.

## Removed from `@cmssy/types`

Twenty-six exports that no repo imported, and that the SDK never re-exported:
the cart, order, product, address, price-tier, shipping and tax-summary
declarations, `CmssyProductPage`, `MyOrdersResult`, `LayoutOverride`,
`LayoutOverrideAction`, and the option bags for fetch and hook functions that no
longer exist (`FetchProductsOptions`, `FetchProductOptions`,
`FetchOrderByTokenOptions`, `CmssyAddToCartOptions`, `UseCmssyOrdersOptions`,
`UseCmssyOrderOptions`, `CmssyStockState`).

None of these was reachable through `@cmssy/core`, `@cmssy/react`,
`@cmssy/next`, `@cmssy/astro` or `@cmssy/remix`, so if you only import from the
SDK this section does not apply to you. If you imported them from
`@cmssy/types` directly, you were using a type for an API surface the SDK does
not serve, and the shape you want is in your own codegen output.
