# v10 → v11

One change, in one component, for one reason: **public routes were never
cached**, in any v10 release.

## What was wrong

A cmssy app declaring `export const revalidate = 3600` served
`Cache-Control: private, no-cache, no-store` on every request. Two independent
causes, both of which had to go:

1. **No `generateStaticParams`.** A catch-all route that generates no params is
   rendered on demand, and `revalidate` is ignored. The scaffold never had one.
2. **`CmssyLayoutSlot` read `headers()`** - through `isCmssyEditMode`, and again
   through the locale fallback when `path` was omitted. One read makes the whole
   route dynamic.

`draftMode()` is *not* a cause; reading it does not mark a route dynamic in
Next 16. If you removed it from your own code chasing this, put it back.

## What to change

### 1. `CmssyLayoutSlot` takes `editMode`

```diff
 <CmssyLayoutSlot
   config={cmssy}
   blocks={blocks}
   position={position}
   path={path ?? []}
+  editMode={false}
   editable={EditableLayout}
 />
```

`false` on your public route, `true` on `/cmssy-edit`. It is required rather
than defaulted because the wrong value is silent: an edit route that says
`false` wraps draft content in published chrome and nothing reports it.

There is deliberately no codemod for this one. A codemod sees a file's contents,
not its route, so it would write `false` everywhere - including the edit route,
where that is exactly the bug this prop exists to prevent. `tsc` names every
call site instead, and you decide each one.

### 2. The locale fallback is gone

A slot without `path` used to read the language off the header the proxy set.
It now takes an explicit `locale`:

```diff
-<CmssyLayoutSlot position="header" ... />
+<CmssyLayoutSlot position="header" locale={locale} ... />
```

Either `path` or `locale`, never neither - the type enforces it. The fallback
went because a cached route never sees that header: it would have rendered the
wrong language and looked like it worked.

### 3. Generate your static params

```tsx
export const revalidate = 3600;
export const dynamicParams = true;

export function generateStaticParams() {
  return publishedPaths();   // your query - see services/pages.ts in cmssy init
}
```

Without this the other two changes buy you nothing.

**Read this before picking a number.** Caching is a tradeoff you did not have
before, because you had no cache: with `revalidate = 3600` a published edit takes
up to an hour to appear, and a URL visited before its page existed keeps serving
a cached 404 for the same window. Wire `revalidatePath` to a publish webhook and
both disappear; until then, set `revalidate` to the staleness you can defend.

## Verify it, do not assume it

On a production build - `next dev` renders everything dynamically:

```bash
pnpm build   # the catch-all should print ● and a Revalidate value, not ƒ
pnpm start
curl -sI http://localhost:3000/ | grep -i 'cache-control\|x-nextjs-prerender'
```

Expect `x-nextjs-prerender: 1` and an `s-maxage`. If you see
`private, no-cache, no-store`, something in the route still reads a dynamic API:
`headers()`, `cookies()`, `searchParams`, or a `fetch` with `cache: "no-store"`.
