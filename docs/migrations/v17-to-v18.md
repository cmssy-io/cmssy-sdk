# Migrating from v17 to v18

v18 removes two fields from `CmssyFormSubmitResponse`: `accessToken` and
`customer`. The delivery API has never returned a value for either - every
return site in the form-submission service sets them to `null`, and the form
action that was meant to fill them (a form that logs a site member in on
submit) does not exist. They were a promise the schema made and the server never
kept.

There is **no codemod**, and that is deliberate. A codemod can rewrite an import;
it cannot decide what your code should do instead of reading a field that was
always `null`. Any branch you guarded on these never ran, so the right rewrite is
a judgement about your own app, not a mechanical substitution.

## What breaks

TypeScript, and only where you named the fields:

```ts
const result = await submitForm(formId, values);
if (result.accessToken) {
  //          ^^^^^^^^^^^ Property 'accessToken' does not exist on type
  //                      'CmssyFormSubmitResponse'
  signIn(result.accessToken);
}
```

Nothing changes at runtime. The mutation no longer selects the two fields, so the
response body loses two `null`s - a payload your code already had to treat as
absent.

## What to do

Delete the branch. It was dead: `result.accessToken` was `null` on every
submission the API has ever answered, so the code inside it has never executed in
production.

If you wanted the behaviour rather than the field - a form that signs a visitor in
on submit - build it on the site-member auth mutations
([docs/auth](../auth/member-auth.md)), which do return a token. The form submission
never did.

## Everything else

Unchanged. Nothing moved, nothing was renamed, no other type changed, and no
regeneration is needed: `npx @cmssy/cli types` produces the same file as on v17.
